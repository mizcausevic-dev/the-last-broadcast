# Decisions

## The case is an exit, not a killing

A missing engineer does not become a murder because the genre usually works that way. June left alive, on purpose, with a copy of the real public file. Ellis's wrongful act is preparing a substitute file and a sign-off she did not make. The accusation form grades that explanation.

Trade-off: players who want a culprit in handcuffs get a paperwork answer. The tone stays inside the content note, and the proof is checkable.

## Structured explanation, graded by the argument

The form has four choices (status, route, purpose, conduct) and exactly three notebook entries. Success requires the right four choices and a trio that covers both the exit and the file contradiction. Right choices with the wrong attachments are "insufficient," not success. Naming Ellis as an abductor is a wrong theory even though his conduct is the real cause.

A motive essay is not required. The purpose control is the explanation.

Support matching accepts a superset. If an authored pair is inside the player's two or three entries, extra held material does not fail the deduction. This avoids a hidden-answer reject.

## One reducer, one projection

Progress flags live in `dispatch`. The view renders `project(state)` and does not import the content module, so locked topics, support keys, and ending paragraphs are not sitting in the view. They are still in the JavaScript bundle. That is disclosed. There is no claim that the browser can hide a solution.

## Monotonic progress

Evidence, statements, and accepted deductions only accumulate. Wrong deductions and wrong explanations change feedback and the attempt count. They do not remove actions. Required objects stay inspectable for the whole investigation.

Exceptions: the ending phase stops play actions. A confirmed reset clears progress. Both are tested.

## Solvability proof

The dependency graph being acyclic is not treated as proof. The check is:

- Required items are producible from the initial state.
- A full action sequence reaches the ending.
- A second order reaches it.
- Optional items can be skipped.
- Bad deductions and bad explanations leave a finishing path.
- A sample of off-path actions only adds state.

The full power set was not enumerated. `PROGRESS.md` states that limit.

## Saves

`localStorage` key `tlb-save-v1`, separate from `tlb-settings-v1`.

Format v1 is current. Format v0 (room, clues, chats) has a tested migration. Any other version is refused. A refused load does not write back. The player can download the raw text or explicitly erase it.

Multi-tab policy: before a write, if the stored revision is not the revision this tab last read or wrote, do not overwrite. The player can load the other tab's night or overwrite on purpose. This is not a lock service. Two tabs can still race if they write in the same instant. It catches the ordinary case.

Quota and security errors leave the in-memory night playable and say that it is not stored.

Saves are not tamper-proof.

## Hints

Hints pick the lowest-priority unmet objective whose condition is already true. The first request is a direction. The same objective escalates up to a third, more explicit line, then stays there. Completing it clears the pin. The next request starts a new objective at the gentle line. Hint count is stored and shown in settings with no score penalty.

Hint text names rooms and objects. It does not state the full resolution.

## Audio

Room tone is generated in the browser with Web Audio. It is off until a click. Volume and mute live in settings. The case does not use sound.

## What this build refuses to add

No backend, accounts, analytics, external fonts, external images, or a content editor. The estate habit of shipping a seven-theme dashboard and a lead form conflicts with this brief's radio-station interface and with its ban on accounts and external services. The game does not carry that dashboard or a form.

Filename habit: standing rules ask for a `-Cursor` suffix. This brief names `PLAN.md`, `PROGRESS.md`, `DECISIONS.md`, and `README.md`. Those names follow the brief.

## Hosting

GitHub Pages was requested. Implementation does not depend on it. The game is a static directory. Push and Pages are done only if credentials exist, and the result is recorded in `PROGRESS.md` from the actual command.
